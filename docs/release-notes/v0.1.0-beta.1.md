## Product promise

Who Am I installs a local Personal Card on macOS and connects it to the
Personal Model owned by the current macOS account. Each downloader creates a
stable random local model ID plus their own name and handle. The production
application does not register Cecilia or Lin; those identities exist only in
development fixtures.

Card, Rewind, Identity, Connector, Report and Evidence requests are bound to
the active model, viewer session and scopes. A model switch commits one complete
Snapshot or preserves the previous Snapshot on failure.

“Your model” means the current macOS account's owner-local Persome data under
`~/.persome`. It is not a pre-trained cloud profile. A new installation may
initially have little activity, no Root, or a model still forming. Permissions,
data import/capture and optional model-provider setup affect how quickly it
becomes useful.

  start and each user prompt.

## Installation flow

1. Download and checksum all assets from one immutable GitHub Release.
2. Run `bash install.sh --interactive`.
3. Open Who Am I and create the local name and handle.
4. Use the in-product button to finish Persome onboarding and macOS permissions.
5. Return to the Card and choose “完成后重新检测”.

The installer preserves Personal Model data and the Card owner profile across
reinstall and update. Product production startup verifies the product-managed
Runtime receipts and uses local stdio MCP rather than trusting an arbitrary
`persome` on `PATH` or an unauthenticated loopback MCP service.

## Verification

```bash
MANAGEMENT_ROOT="${PERSOME_INSTALL_HOME:-$HOME/.persome}/product-management"
bash "${MANAGEMENT_ROOT}/scripts/diagnose.sh"
bash "${MANAGEMENT_ROOT}/scripts/verify.sh" --quick
bash "${MANAGEMENT_ROOT}/scripts/verify-product.sh"
```

Run Runtime `--full` verification only after permissions and provider/model
setup are complete.

## Supported platform

- macOS 13 or newer.
- Apple Silicon and Intel.
- Xcode Command Line Tools and network access during installation.

## Known limitations

- The app is not signed or notarized.
- The first install downloads pinned Python, OCR and Node dependencies and can
  take several minutes.
- macOS permissions cannot be approved automatically.
- Root/Faces may remain sparse until enough data exists and a model provider is
  configured.
- The optional Codex plugin sends bounded recalled passages into the active
  Codex conversation under that account's data controls.
- Product-app removal is not automated in this candidate. Runtime removal is a
  separate preserve-data or confirmed-delete operation.
- Intel and minimum-macOS clean-machine evidence, the final GitHub repository,
  product license, support route and rollout owners remain release gates.

See `docs/known-issues.md` and `docs/release-checklist.md` before distribution.
