# v0.1.0-beta.3 — Per-user Card isolation

This source candidate fixes a production fallback that could show development
Card content when a new user's Personal Model was unavailable or a model
operation failed.

## What changed

- Production starts behind the local setup gate and opens the Card only after
  the current user's complete model Snapshot has been committed.
- A transient Ask or Correct failure no longer replaces the current user's
  Snapshot with development fallback data.
- Public-card questions use the active model's scoped Provider instead of a
  hard-coded local answer.
- Development fixtures and Offline Replay are excluded from the installed
  production payload.
- Cecilia and Lin remain available only in development mode for runtime-switch
  and six-module isolation tests.
- Production Card activity labels no longer contain publisher-specific rules.

## Verification

- Fresh HOME with no Runtime returns setup-required and renders no development
  identity or Card content.
- The installed payload contains no Cecilia, Lin, publisher account, or known
  development Card copy.
- Cecilia/Lin runtime switching still passes across Card, Rewind, Identity,
  Connector, Report, and Evidence.
- Production owner onboarding and restart retain only the downloader's stable
  local model identity.

## Runtime delivery

The Personal Model Runtime is local software, not a hosted cloud backend. The
installer anonymously fetches and verifies the exact public Runtime commit
recorded in `runtime.lock`, then installs it under the current macOS account's
`~/.persome`.

This candidate remains `RELEASE_STATUS=HOLD`; no GitHub Release asset or tag is
published until the release checklist is approved.
